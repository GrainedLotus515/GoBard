# NF source acquisition verification — 2026-10-16

This is a real provider/codec test with fake voice delivery, not a Discord
listening test. It exercises the new bounded acquisition path against two public
album entries implicated in the October 15 investigation. Their historical
zero-frame failures remain unexplained; successful new requests cannot identify
the earlier cause.

The opt-in `TestProviderNFColdAndWarm` uses real yt-dlp, the production YouTube
opener, FFmpeg/libopus and a 20 ms paced output sink. Each track starts with its
own empty 16 MiB temporary cache, then replays from cache with the extractor
executable deliberately unavailable. Replay is unpaced and must reproduce the
entire cold frame count. The engine has no retry; no recovery occurred.

| Track / public ID | Cold result | Cold first frame | Cold elapsed | Warm result | Warm first frame |
| --- | --- | --- | --- | --- | --- |
| MOTTO / `8fM1xnLTApg` | completed, 10,864 frames | 2.026 s | 219.287 s | completed, 10,864 frames | 73.039 ms |
| PANDEMONIUM / `zpp6ZvJ351Q` | completed, 9,851 frames | 1.817 s | 198.818 s | completed, 9,851 frames | 142.293 ms |

Test process passed in 420.60 seconds. Warm elapsed times were 1.320 and 1.172
seconds because replay was unpaced. These two startup observations are not p95
measurements. The test does not establish full-album reliability, Discord packet
delivery, human audibility or immunity to provider rejection. The older paced
MOTTO probe reset after 166.861 seconds; see [the investigation](live-2026-10-15.md).
The difference supports testing the new acquisition design further, not a claim
that every network reset has been fixed.

Executed image:
`sha256:bc3d6c56cad4c37ec72f9eec48fa246d79b2a217dc9b870b81ff50f187990b08`.
Host: Intel Core i9-12900K, linux/amd64. Container: two CPUs, 512 MiB memory,
128 PIDs, UID/GID 1000, read-only root, 128 MiB temporary filesystem. No Discord
token, cookies, account credentials or persistent cache were mounted. This image
preceded removal of the unused cache-creator API; the exercised transaction and
acquisition implementation were unchanged by that simplification.

Reproduce only when an external provider check is intended:

```sh
docker build --target provider-check -t gobard-provider-check:local .
docker run --rm --read-only --user 1000:1000 \
  --tmpfs /tmp:rw,noexec,nosuid,size=128m --memory 512m --cpus 2 --pids-limit 128 \
  -e GOBARD_PROVIDER_CHECK=1 gobard-provider-check:local
```

The default offline test suite skips this test. Its output contains outcome,
frame/timing metrics and allowlisted failure classification only, never raw
extractor diagnostics or signed media URLs. Full listening acceptance still
requires two isolated cold album passes, one warm pass, controls/reconnect and
the two-guild session described in [the checklist](acceptance-checklist.md).
